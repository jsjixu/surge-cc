# 隔离工程、同项目历史与本机智能体通信

Surge CC 的项目管理命令把现有工程复制成一个新的、已登记的隔离工程。原目录保持不变。Orca 应打开这个副本，并从副本创建工作树；工作树的源码各自独立，同一项目、同一 Surge CC 工作区账号可以共用对话历史和本机消息目录。

不需要另装 Skill。项目管理逻辑已包含在应用和源码发行版中；首次设置向导可以调用相同接口。这个功能不负责提供代理节点、Claude 订阅或登录凭据。

## 建立副本

先完成 Surge CC 的线路设置、专用浏览器和终端接管。以下示例在源码仓库运行；安装包中的同一命令位于：

```text
/Applications/Surge CC.app/Contents/Resources/scripts/surge-cc
```

1. 预览要保留的文件、排除项、目标路径及当前账号：

```sh
./scripts/surge-cc project plan \
  --source /absolute/path/to/your-project \
  --name my-project \
  --json
```

默认目标是 `~/Documents/Codex/Claude-Isolated/projects/my-project`。名称使用小写字母、数字和连字符，以字母开头，最多 40 个字符。通过 `--root` 指定自定义根目录时，预览和应用必须传入同一个根目录；已有注册表不能被这个选项改指向。

2. 检查返回的 `project.files`、`project.excluded` 和 `project.review_notice`。项目快照不是秘密扫描器：普通源码里写死的密钥、客户资料或其他不应发送的内容仍需要自行检查。
3. 把返回的 `project.digest` 用作下一步的 `--plan-id`：

```sh
./scripts/surge-cc project apply \
  --source /absolute/path/to/your-project \
  --name my-project \
  --plan-id REVIEWED_DIGEST \
  --json
```

如果源码内容、排除清单或当前账号改变，应用会要求重新预览。已存在的目标不会被覆盖。应用失败时，原工程保持不变；本次新建的副本及注册信息会回滚。

默认开启同项目对话历史和本机消息通信。可用 `--no-shared-history` 或 `--no-messaging` 在创建时不启用相应能力。需要让已登记副本及验证通过的 Orca 工作树默认信任时，明确加 `--trust`；这个选项不信任原目录或机器上的其他目录，也不会覆盖原生 Claude 已保存的显式拒绝信任。

创建完成后会生成 `SURGE-CC-HANDOFF.md`，列出保留的工程文档与构建入口。它不会从旧聊天或旧记忆中总结内容，也不会包含账号凭据。副本会建立新的本地 Git 历史；原仓库的提交历史、远端配置和 hooks 都不导入。

## 哪些内容不会导入

预览会完整列出实际排除项。保守过滤包括：

- 旧 `.git`、`.claude`、`.claude.json`，以及常见 AI 工具账号目录。
- `.env*`、常见 token/credentials/secrets 文件名、私钥和证书容器。
- 浏览器状态、会话、调试日志、构建产物、依赖目录和缓存。
- 符号链接、硬链接、特殊文件，以及其他用户拥有或可被其他用户写入的内容。

过滤按名称和文件属性执行，不会运行工程脚本，也不检查被排除凭据文件的内容。`.env.example` 也保守排除；需要的无秘密模板可在审核后重新建立。对于含子模块或必须使用符号链接的工程，先准备一个自包含的源码快照；导入器不会跟随链接扩大读取范围。

文件数量、单文件大小、总大小与目录深度有上限。整个个人主目录及常见个人资料总目录不能作为工程导入。导入失败会停止，而不是缩减边界后继续。

## 在 Orca 中使用

将输出的 `project.path` 添加为 Orca 项目，并在其中创建新工作树。不要把原工程重新添加到同一个隔离身份，也不要手动复制注册标记到无关目录。

运行 `claude` 时，启动器会检查：登记路径、私有运行目录、工作树到主仓库的 Git 指向、当前账号、线路保护及文件沙箱。新工作树的 `HOME` 独立，但可以获得以下精确共享：

| 内容 | 范围 |
| --- | --- |
| 工程源码 | 仅当前副本或当前工作树可读写 |
| Git 公共数据 | 可读同仓库历史；可写 objects、refs、reflogs 和当前工作树状态，配置、hooks 与关联元数据受写保护 |
| `/resume` 对话 | 同一个登记项目、同一个 Surge CC 工作区账号 |
| `/list-agents` 与本机消息 | 同一个登记项目、同一个 Surge CC 工作区账号 |
| 自动记忆与其他 HOME 数据 | 工作树各自独立 |
| 登录 | 使用当前 Surge CC 账号的独立认证配置，不从原工程复制 |

Git 与依赖安装、插件/hooks 和本地预览的支持边界见 [隔离项目内的日常开发](ISOLATED-DEVELOPMENT.md)。这些会话要求 Surge 规则模式，线路失败后不会换出口；宿主凭据和其他项目文件不会因此开放。

对话共享意味着该项目的其他智能体可以读取并恢复已共享对话；不要把需要互相保密的任务放在同一项目账号范围。跨项目、跨账号不会合并。恢复较早的对话时，当前工作树的文件和分支仍是当前工作树，不会自动切回旧文件状态。

原生本机消息仍遵循 Claude 自身的接收权限规则。可用 `/rename 名称` 区分智能体，用 `/list-agents` 查看同范围在线会话；不同权限模式的消息可能需要接收方批准。短 socket 目录解决 macOS 路径长度问题，不需要开放系统临时目录或更改已配置的代理线路。

## 给已有隔离工程启用这些功能

先查看状态：

```sh
./scripts/surge-cc project status --json
```

预览当前账号的原生历史候选数量：

```sh
./scripts/surge-cc project enable-plan --name my-project --json
```

然后正常退出该账号下的 Claude 与专用浏览器，再运行：

```sh
./scripts/surge-cc project enable --name my-project --trust --json
```

可以重复 `--name` 精确选择多个已登记项目。历史初始化只处理当前账号在这些隔离 HOME 中生成的记录，保留原始记录作为回退副本，不读取个人 HOME 或封存目录。相同共享库初始化完成后不会重复导入、覆盖后来的对话。

仍在运行的 Claude、专用浏览器或未修复的浏览器锁会阻止迁移。不会强杀进程或跳过排他锁。若发现旧隔离数据尚无可信的账号归属记录，会拒绝猜测归属；应先完成原账号迁移。

切换到新的 Surge CC 账号后，需要在该账号下运行一次 `project enable`，初始化这个账号自己的共享库。它不会复制上一个账号的对话。未初始化时会阻止对应的隔离启动，并提示先设置；不会退回其他账号的历史库。

已有进程继续使用启动时的边界。完成启用后，正常 `/exit` 并重新运行 `claude` 才能获得新的通信和历史目录。

## 范围与验证

本功能管理经 Surge CC 启动的本机 Claude；它不是整台 Mac 的通用防火墙。线路保护仍要求已配置的 Surge 规则、专用入口和进程边界正常生效。项目导入本身不修改代理线路、普通浏览器、系统时区或现有 其他代理线路。

自动化测试使用合成工程和合成对话，覆盖只读预览、排除规则、源码变化检测、回滚、旧浏览器锁、运行期会话排他、账号归属、同项目历史初始化以及从新副本创建的真实 Git 工作树。不会在测试中读取用户 Token 或提交模型请求。
