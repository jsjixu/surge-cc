# 隔离项目内的日常开发

隔离保护针对已经登记的项目副本和 Orca 工作树，作用于受控入口启动的 Claude Code 及其子进程。它不是整台 Mac 的全局沙箱。

## 可用范围

- 当前工作树、该工作树的独立 HOME、缓存、依赖目录可读写。系统命令、开发工具、TLS 配置和证书仅开放必要的只读路径。
- Git 可以读取同仓库的提交与分支，写入 objects、refs、reflogs 及当前工作树状态，支持 add、commit、fetch、push。其他工作树的工作文件不开放。
- npm/pnpm 的缓存和安装目录留在隔离 HOME；项目内的 `node_modules/.bin` 可以使用。安装脚本与构建子进程继承同一个文件和网络沙箱。
- 当前隔离 HOME 和当前项目内的 Claude 设置、插件、skills、commands、hooks 可以加载。Orca 自动标题 hook 与它们合并。不会复制或读取原账号 HOME 的 hooks。
- 沙箱内的 `claude plugin …` helper 支持插件管理；启动新模型会话仍使用 Orca/Ghostty 中的受控入口。

## 本地预览与线路

每个受控启动有一个短期本机 HTTP/CONNECT 代理。公网请求只能转发给已经验证的 Surge 专用入口；不解析公网域名或直连公网，也没有第二个上游。

本地预览可通过这个代理访问 `localhost`、`127.0.0.1` 或 `::1`。代理核对监听进程必须属于**此次 Claude 启动的子进程树**；另一个会话、项目或宿主程序的本机端口不开放。支持 HTTP、CONNECT 和本地 WebSocket 热更新。浏览器直接打开当前开发服务器的本机地址也可以；这不修改普通浏览器的代理设置。

隔离开发会话要求 Surge 处于规则模式，不适用普通入口的全局模式挂起行为。启动、建立连接和运行期间都会检查固定节点；成功的连接前检查最多在同次启动内复用一秒。失败后关闭连接并锁定本次开发代理，不跟随 Surge 的全局模式或备用节点；检查和巡检仍有延迟，不是瞬时防火墙。Claude 子进程只能连接该次开发代理，不能自行直连 Surge 的普通代理端口或公网。

常用 Git、curl、npm/pnpm 会读取代理环境变量。自行建立网络连接的程序仍需要显式配置代理，例如 Playwright 的浏览器。没有配置代理的直接连接会被拒绝，不会静默换出口。

## 继续保留的限制

- 个人文件夹、其他项目、其他账号 HOME、旧 Claude 会话和宿主凭证仍不开放。
- 同项目的共享对话和通信继续按既有账号范围共享；其他项目、账号不共享。
- SSH agent、宿主 SSH/GitHub 凭证和系统钥匙串不继承。私人远端的 fetch/push 需要隔离环境自己的授权，或在 Orca 宿主操作。
- 共享 Git config、hooks、工作树关联文件不可改写；`git remote add/set-url` 等应在宿主完成。这避免沙箱内插件把命令注入宿主的后续 Git 操作。
- MCP、宿主浏览器控制、远程控制和任意额外目录仍关闭。插件的普通 skills/commands/hooks 可用，不等于开放插件附带的全部宿主集成。
- 不支持借助这个 helper 更换账号、更新 Claude 本体或启动未受控的新会话。

## Orca 标题和旧版权限规则

自动标题通过每次启动单独建立的最小桥接通知 Orca。它只向已经核验的当前标签页转发生命周期事件和提交 prompt 的前 512 个字符，不向 Claude 提供 Orca 的通用令牌或宿主 hooks。标题模型由 Orca 自己的设置决定。桥接失败时可继续手动命名，文件和线路保护保持启用。

旧版本曾在项目 `.claude/settings.json` 中放入覆盖整个 `~/orca/**` 的 Read/Edit 拒绝，可能导致当前工作树提示 `Instruction file not loaded (a Read deny rule covers it)`。v0.5.1 启动器只在验证项目归属后迁移完整匹配的旧 12 条模板：先备份，再删去误伤 Orca 当前工作树的两条规则。剩余规则、自定义内容、部分模板以及 `settings.local.json` 保持原样。

备份位于该工作树独立 HOME 的 `.surge-cc-settings-backups/`，目录仅本人可访问，备份文件权限 `600`。迁移拒绝链接、硬链接、异常归属及并发修改，不会因修复提示而关闭 Seatbelt。已存在和之后新建的工作树都在下一次受控启动时按需处理；没有匹配模板时不会删除用户自定拒绝规则。

## 生效与验证

已运行的 Claude 不会被热修改。正常 `/exit` 后重新启动才使用新策略，同项目历史仍可 `/resume`。

验证包括真实 macOS Seatbelt 下的 TLS、Git 操作、依赖安装、构建、插件和四层 hooks 合并；文件跨界、硬链接、直接网络和无关本机端口均须被拒绝。故障测试使用独立测试代理注入异常，不需要关闭用户正在使用的线路。
