# 本机已验证体验与 0.4.0 发布能力对照

这是功能迁移对照，不包含参考机器的节点、账号、源码或会话。发布版把原先本地维护的补丁整合为同一套后端，通过随包向导完成一次性配置。

| 参考安装的体验 | 0.4.0 中的实现 | 新用户需要做什么 |
| --- | --- | --- |
| App、Ghostty、Orca 启动前检查线路 | 同一启动后端与受控 `claude` 入口 | 向导应用规则并安装终端接管 |
| 专用网页和 OAuth 使用同一登录环境 | 每工作区独立 Browser/Default + OAuth 回调核验 | 自己登录该工作区账号 |
| 固定节点、失败不自动换出口 | 规则模式单节点、专用入口与旁路拒绝规则 | 提供自己的节点和准确出口，开启增强模式 |
| 各智能体只能访问授权工程与 HOME | 副本登记、Orca 关联验证、macOS Seatbelt | 向导选择工程副本，Orca 从副本建立工作树 |
| 新工作树不反复初始化主题 | 独立 HOME 加安全偏好继承 | 首次完成原生引导，之后复用该账号已学到的偏好 |
| 精确项目默认信任 | 项目 allowlist，不全局信任 | 导入或启用时明确选择信任 |
| 同项目新工作树能恢复对话 | 按项目和账号共享会话库 | 停止旧会话，预览后启用共享 |
| 同项目智能体能互相通信 | 短路径本机 socket、同范围会话发现 | 启用本机通信，双方重新从受控入口启动 |
| Orca 截图可被 Claude 读取 | 明确粘贴 PNG 的限额导入桥接 | 使用受控交互终端，不需开放系统临时目录 |
| 默认 Opus / High | 当前工作区可配置模型和 Effort | 选择 `opus` / `high`，或账号支持的精确模型 ID |
| Dock 一点打开，已有窗口复用 | 通用 Swift 入口，严格验证浏览器与守护身份 | 创建入口，可自定义名称；主 App 保持安装位置 |
| Dock 冷启动只显示新标签页 | 保存的 `newtab` 启动选项 | 在启动偏好选择新标签页 |
| 原项目有可用交接资料 | 保留源码和已有文档，生成文件清单式交接摘要 | 审阅排除清单；业务语义摘要仍由项目维护者补充 |
| 不显示 Grok 刷新提醒 | 属于 Orca 个人账号／显示设置 | 在 Orca 中管理，不随本工具对其他用户执行 |

## 软件与一次性设置的边界

安装包已经带齐程序逻辑、预编译 Dock 模板、配置向导和项目管理工具，不需要再安装 skill。首次配置的节点、账号授权、依赖安装和工程审阅必须由用户完成。无法把一个 ZIP 同时当作 Surge 许可证、住宅网络和已登录账号。

源码过滤不会证明工程没有敏感信息；交接文件是工程文件清单，不是假称理解了业务的 AI 摘要。同项目共享完整历史会包含已存在的对话内容，但不会扩展其他工作树文件权限。旧图片／plans／文件回退引用可能继续不可读；会话互发消息保留原生权限审批。账号边界由用户正确使用工作区绑定维持，不自动识别登录者。

## 验证如何解读

- 参考安装此前完成过真实 Orca 图片识别、跨工作树恢复、两会话互发消息及 Dock 冷启动／复用测试。
- 0.4.0 发布验收重新检查新增通用入口、旧配置兼容、合成全新目录中的配置与项目复制、账号边界、打包代码一致性和签名。详细次数以 [VALIDATION.md](../VALIDATION.md) 为准。
- 合成验收不使用参考机器的 Cookie、Token、真实项目或模型请求，也不声称已在另一台全新 Mac 的所有系统版本上验收。网络服务和模型可用性仍需新用户首次检查。
- 参考机器当前的应用、终端部署、项目注册表和 Surge 配置以发布前后摘要对照；发布流程不为了测试覆盖正在顺畅工作的安装。
