# 隔离会话的 Orca 自动标题

隔离启动原先使用 `disableAllHooks: true`，并移除 Orca 环境变量，所以即使 Orca 的自动标题开关已打开，也收不到 Claude 的提示词通知。本次修复为已登记的隔离项目增加独立的本机标题桥。

## 使用

保持 Orca 的自动生成标签页标题设置开启，从 Orca 终端或终端模式新建 Claude 会话，使用 Surge CC 接管的 `claude` 入口。启动时会显示：

```
[Surge CC] Orca 自动标题已接通，仅通知当前标签页。
```

提交第一条普通提示词后，Orca 根据该提示词在本机生成标题。Orca 1.4.237 的实现不为此调用模型。手动设置的标题、快捷命令标题及已有自动标题会保留，不会被本桥覆盖。

已经运行的 Claude 不会被热修改。正常退出后重新启动即可接入，原会话可继续使用 `/resume`。Ghostty 没有 Orca 标签页，因而不启用这个标题桥。远端 Orca 入口及 Native Chat 的标题不属于本次验收范围。

## 权限边界

- 启动器在沙箱外核对本机 Orca 的项目路径、工作树、标签页和 pane，固定通知目标。
- 每次启动创建私有 Unix socket；隔离进程只获得该次启动的通知能力。Orca 的通用鉴权 token、宿主 CLI、宿主环境变量不传入隔离进程。
- 只接收 `SessionStart`、`UserPromptSubmit`、`Stop`、`SessionEnd`。提示词最多 512 个字符；不转发会话全文、`transcript_path`、工具输入输出、账号信息或任意目标地址。宿主响应不返回给 Claude。
- 首个原生 session UUID 绑定此次桥接；不同 UUID 的事件被拒绝。桥随受控子进程结束清理，并限制请求大小、速率与数量。
- 不读取、复制旧 `~/.claude/settings.json` 的 hooks。隔离开发模式允许当前隔离 HOME 和当前项目的设置、插件及 hooks；标题 hook 与它们合并，全部受同一文件与网络沙箱约束。MCP、宿主 IDE/Chrome 和任意额外目录仍关闭，详见 [隔离开发说明](ISOLATED-DEVELOPMENT.md)。
- Claude 原生的组织管理策略是另一层设置；`--setting-sources` 本身不表示屏蔽组织策略。它们仍受相同的操作系统文件及网络沙箱约束，本修复不修改或绕过管理策略。
- 标题桥只连固定的本机 Orca 回调；指定线路 检查、专用代理和运行期线路监控保持原实现。标题通知失败不会改用宿主 hooks 或非隔离启动。

## 验证

在 macOS / Orca 1.4.237 / Claude Code 2.1.296 上，分别验证了合成沙箱事件及一次原生最小请求：新标签页真正自动命名。隔离进程仍不能读取宿主 Claude 配置、隔离目录外的文件，或直接连接 Orca 的通用回调端口。

自动化测试覆盖字段清洗、目标绑定、跨会话拒绝、凭证隔离、退出清理和启动失败行为。具体本机部署记录与临时测试报告不随公开源码发布。
