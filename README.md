# Surge CC

**在 Mac 上用 Surge 为 Claude 网页和 Claude Code 管理固定线路。**

规则模式下，启动前核对节点和实际出口，检查 DNS 与 WebRTC，通过专用浏览器打开网页及 OAuth 授权，并在运行期间持续检查线路。普通网页和非隔离 CLI 可在全局代理模式挂起出口保护；已登记隔离项目必须使用规则模式。提供原生 macOS 窗口和命令行。

当前版本：**0.5.1（Build 17）** · macOS 13+ · Apple Silicon 安装包 · 界面以中文为主

Surge CC 是独立社区工具，与 Surge、Anthropic 或 Google 没有官方隶属关系。它管理本地连接和程序，不提供代理节点，也不保证账号状态或服务资格。

## 能做什么

| 功能 | 行为 |
| --- | --- |
| 固定线路 | 核对单节点策略组、实际选中节点、规则和精确公网出口；不自动接受变化后的 IP |
| 专用网页窗口 | 使用独立 Chrome 应用副本及独立资料目录；通过专用 HTTP 入口访问，核对浏览器旁路拒绝规则 |
| Claude Code 启动 | 注入专用代理环境，启动前复核线路；保留项目目录及终端交互 |
| 终端入口接管 | 可选安装到现有 `claude` 命令，供 Ghostty、Orca 终端和其他调用该入口的本机终端使用 |
| OAuth 授权 | 从受控 CLI 自动打开专用授权窗口；打开前检查线路，仅放行本次登录的精确本机回调端口 |
| DNS 检查 | 分别检查本机接管迹象和专用代理链的外部 DNS 观测；0.2.3 新增随机域名实测 |
| WebRTC 检查 | 通过临时 Chrome 收集真实 ICE 候选；发现额外公网地址时阻止启动 |
| 运行保护 | 定期复核线路；异常时尝试停止由本工具启动并持有的程序，显示停止结果 |
| 多账号工作区 | A/B 分别保存浏览器资料、CLI 凭据与线路；结束旧受控会话后切换，保留原有登录，不自动搬移个人 Chrome 或 `~/.claude` |
| 专用浏览器恢复 | 关闭当前工作区经过核验的专用窗口，退出后归档残留锁，成功后自动重新检查；已有 CLI 可继续工作，保留登录资料及个人 Chrome |
| 全局代理挂起 | 全局代理模式允许网页与非隔离 CLI 启动，挂起固定出口与断线阻断；隔离项目拒绝启动；直连和未知模式仍阻止启动，不自动切换 Surge 模式 |
| 项目文件隔离 | 向导预览并创建工程副本，原项目不变；登记副本及 Orca 关联工作树，独立 HOME 和文件沙箱 |
| 同项目对话接续 | 可选共享同项目、同账号会话库，让新工作树可以恢复此前对话；跨项目和账号不共享 |
| 本机智能体通信 | 可选建立同项目、同账号短路径 socket，保留原生消息授权；不开放跨机器通信 |
| Orca 图片粘贴 | 将明确粘贴的合规 PNG 导入当前隔离 HOME，支持原生图片附件，不开放整个临时目录 |
| 模型与启动页 | 按工作区保存模型、Effort 和 Claude／新标签页选择；显式 CLI 参数可覆盖模型与 Effort |
| Dock 快捷入口 | 可自定义名称和工作区；检查线路后打开或激活专用浏览器，使用主应用同一套后端 |
| 修复预览 | 先列出改动，确认后备份、校验并修复指定组及相关规则；保留无关配置 |
| 更新维护中心 | 检查终端接管、核验并登记官方原生 Claude Code，保持受控入口；账号和代理设置不变 |
| 错误处理入口 | 按实际失败项提供浏览器恢复、终端维护、线路预览或系统设置入口；处理后重新检查 |
| Surge CC 更新 | 手动检查正式发布，下载并验证安装包；同路径安装、自检失败回滚、保留旧 App |
| Orca 启动诊断 | 显示不同入口的支持范围，并可在已登记的本机 Orca 项目里打开受控终端 |

**规则模式下“异常时停止”有明确范围：** 固定组不含备用节点，专用入口不会主动改走其他出口；进程监控仍有轮询间隔，依赖 Surge 的规则模式、增强模式和有效规则。它不是操作系统防火墙，也不能约束任意忽略代理的 CLI 子进程。完整边界见下文。

## 安装与首次配置

需要 **macOS 13+、Surge for Mac、官方 Chrome、官方本机 Claude Code、Python 3.9+**，以及你自己可用的节点和准确出口 IP。安装包不包含这些第三方软件、线路、账号或凭据。当前验证环境为 Apple Silicon、Surge 6.9.1、Claude Code 2.1.296。

1. 从 [Releases](https://github.com/jsjixu/surge-cc/releases/latest) 下载 ZIP 和 SHA-256，核对后解压，将 `Surge CC.app` 放到 `/Applications`。
2. Surge 中准备一个现有节点和一个可查询的手动策略组，使用普通本地配置文件；规则模式与增强模式保持开启。
3. 打开 Surge CC，点击顶部 **「配置向导」**。向导在终端中展示每一步计划，确认后执行。它会准备独立完整 Chrome 副本、专用 `127.0.0.1:62919` 入口、窄范围的旁路拒绝规则及终端接管。
4. 向导可继续创建隔离工程副本、启用同项目历史／通信、默认目录信任，以及创建 Dock 入口。把返回的**隔离副本路径**添加到 Orca，后续工作树由 Orca 创建。原项目保留。
5. 在「工作区」中自行设置该账号的 OAuth 或通过安全输入保存 setup-token；网页账号也由自己登录。运行「检查线路与隐私」，通过后开始使用。

也可以直接启动同一向导：

```sh
/bin/bash "/Applications/Surge CC.app/Contents/Resources/scripts/first-run.sh"
```

只检查依赖、不应用配置：

```sh
/bin/bash "/Applications/Surge CC.app/Contents/Resources/scripts/first-run.sh" --doctor
```

向导不自动购买节点、下载依赖或代替用户登录。准备规则前会展示备份和修改计划，应用规则可能短暂重载 Surge。项目导入按文件名排除已知认证、会话、日志、缓存及旧 Git 元数据；它不会判断任意源码是否含有秘密，用户仍需审阅保留清单。

**为什么用脚本补充而不是 skill？** 首次安装需要稳定地检查文件、锁、路径、签名、线路和迁移结果，脚本可以预览、重复执行及验收。运行脚本不需要另一个 AI 或特定 skill。安装后日常使用仍通过 App、Dock 或终端入口。

完整步骤、旧版升级与命令行方式见 [首次配置指南](docs/SETUP.md)；工程管理见 [项目与会话指南](docs/PROJECTS.md)；本机体验与发布包对照见 [功能对照](docs/PARITY.md)。

此发布包为 **Apple Silicon、ad-hoc 签名，未经过 Apple 公证**。macOS 可能阻止首次打开；核对来源后使用系统「隐私与安全性」提供的单个应用打开入口，不需要关闭整体 Gatekeeper。没有相应选项时可从源码构建。新版 ad-hoc 包可能需要重新授予隐私权限，见 [签名说明](SIGNING.md)。Intel 可从源码构建，但尚无真实机器验收。

**先把 App 放到最终位置，再运行向导。** 终端与 Dock 入口引用主应用绝对路径；移动或删除主应用后，需要重新配置，缺失时会阻止启动。仅检查或下载安装包不会替换现用的安装；只有明确点击「安装并重新打开」并确认后，才会执行同路径升级。

## 日常使用

### 网页与 CLI

- **网页：** 从 Surge CC 点击「打开专用浏览器」，进入专用窗口。
- **CLI：** 先选择项目文件夹，再点击「启动 Claude Code」；Terminal 内部启动前会再次复核。
- **切换账号工作区：** 在「工作区」选择 A 或 B 可先预览。保存网页草稿和 CLI 工作后，点击切换并确认结束当前专用会话；下一次网页、OAuth 和 CLI 启动一起使用目标账号环境。
- **固定节点：** 「固定指定节点」选择已有单节点组中的目标并重新检查，不修改配置文本。
- **查看保护：** 刷新保护状态，查看最近心跳及时间。关闭 Surge CC 窗口不等于关闭独立网页监控。
- **专用窗口占用：** 点击错误下的「关闭专用窗口并修复」，或从「工作区」页操作；会中断当前专用窗口的网页和授权，成功后自动重新检查。
- **全局代理模式：** 显示「保护已挂起」，仍可打开专用网页、启动非隔离 Claude Code 和完成专用 OAuth；已登记隔离项目要求规则模式；固定出口与断线阻断暂停，流量依 Surge 全局策略。回到规则模式后重新检查，才能恢复保护。
- **直连或未知模式：** 仍阻止启动。应用不会替你切换 Surge 模式。

个人 Chrome 不受这些启动规则影响。未安装终端接管时，直接运行 `claude` 不会经过启动检查；安装后，调用被接管的同一个命令入口才会自动检查。

### A/B 多账号切换

一个工作区对应一套账号环境。网页和 CLI 都支持各自的登录，但 Surge CC 不读取账号资料来自动判断两边是否属于同一个人；请自行确认账号一致。

| 内容 | A/B 的行为 |
| --- | --- |
| 网页和 OAuth | 每个工作区固定使用自己的 `Browser/Default`，两种入口共用该资料；其他工作区和个人 Chrome 不会被复制 |
| Claude Code | 各自的本地配置与 OAuth 存储；可另选各自的 macOS 钥匙串 Token |
| 线路与预期环境 | 分别保存节点、策略组、预期 IP、专用入口、浏览器语言及检查参数；同一节点仍对应同一出口 |
| 已登记隔离项目 | 项目源码保持共享；各账号使用独立运行 HOME、会话、记忆和账号凭据 |
| 安装与全局状态 | Surge 配置文件路径、专用浏览器程序路径、CLI 进程范围及 Surge 出站模式仍为整机共用 |

升级保留当前工作区的原浏览器资料；已有旧版钥匙串 Token 只把引用绑定到升级时的当前工作区，不读取、复制或重新生成 Token。新工作区首次使用只复制当前的线路设置作为起点，之后独立保存；不会复制 Cookie 或 CLI 凭据。旧版非 Token 工作区会保留原 OAuth 路径及钥匙串命名空间；普通 CLI 的原生钥匙串与隔离 CLI 的文件回退仍可能需要分别授权。已有 Token 模式在两种启动方式中统一注入，不需要因此重新生成 Token。

**第一次添加第二个账号：**

1. 在 A 中保存网页草稿和 CLI 工作。若需要备份，先正常结束专用会话，再保存 A 快照。
2. 打开「工作区」，选择 B 查看预览，再点击切换并确认结束旧工作区的受控会话。只有界面显示「当前：B」才表示切换完成，单纯在下拉框选 B 不会改变正在使用的账号。
3. 在「编辑当前工作区线路」确认 B 的节点和预期 IP。初始值从 A 复制，但之后独立保存；需要不同出口时，填入自己已有的节点与准确出口，再通过修复预览应用并检查。仅切换账号不要求购买第二条线路。
4. 使用「打开专用浏览器」进入 B 的专用浏览器，自行登录第二个网页账号。先正常关闭专用网页窗口，再选择「使用独立 OAuth」并启动 Claude Code 完成该账号的授权；也可用「保存此账号的 Token」保存已有的订阅 Token。网页和 CLI 要分别具有有效登录，网页已登录不等于 CLI 已授权。
5. 以后保存工作后，从同一入口切回 A 或 B。重新打开网页或 CLI 时，会使用该工作区上次保存的登录与线路。切换不会自动打开程序、发起授权或开始任务。

Token 只经安全输入写入该工作区的钥匙串条目，具体范围见 [TOKEN-AUTH.md](TOKEN-AUTH.md)。浏览器和 CLI 的凭据状态只说明本地资料是否存在，应用不会代替服务验证订阅是否有效。

切换会先结束当前及目标工作区由新版 Surge CC 管理的会话，再应用目标线路并提交当前账号选择；不会把正在执行的 CLI 任务搬到另一个账号，也不会自动重新打开网页或登录。旧版会话、无法确认归属的窗口或未释放的锁会阻止切换，需先正常退出。线路不同可能需要重载 Surge，保留其他节点与无关规则，重载可能导致现有连接短暂重连。切换失败时账号保持原选择，能确认归属的线路改动会尝试回滚；已结束的任务不会自动恢复。

此版本的 CLI 认证范围是 **claude.ai 订阅 OAuth / setup-token**。不支持把 Anthropic Console 登录当作另一类工作区账号；也不接管个人浏览器或其他程序的全局认证。普通网页和非隔离 CLI 在 Surge 全局模式下仍可挂起保护，账号资料保持分开。已登记隔离项目必须使用规则模式，公网只经专用上游 `127.0.0.1:62919`；切换工作区不会解除这些限制。

v0.3.0 已在真实机器完成 A→B→A：B 网页及 CLI 均为未登录状态，切回 A 后原登录保留，两种 B 受控会话一起退出。自动化覆盖不同线路的切换与失败回滚；实机测试沿用同一节点，未使用两个真实订阅账号发送模型请求。详细记录见 [VALIDATION.md](VALIDATION.md)。

### 在 Ghostty、Orca 等终端中直接运行

自 0.2.4 起提供可选的终端接管。它原子替换当前用户的 `~/.local/bin/claude` 符号链接入口，保存原链接和原始程序信息；不修改整个终端应用的代理，也不改变其他节点或普通浏览器。

安装前先正常结束已有 Claude Code 会话，并确认：

1. 使用官方原生安装，`~/.local/bin/claude` 目前是符号链接；其他安装布局会拒绝自动接管。
2. Surge CC 的 `config.json` 已设置 `cli_process_paths`。常见原生安装使用当前用户 `~/.local/share/claude/versions/` 的**完整绝对路径，并保留尾部 `/`**。不能填写 `~`，也不能把范围设成 Ghostty、Orca、Node、Python 或整个主目录。
3. 执行 `repair-plan` 查看新增的 Claude 程序路径 `PROCESS-NAME,...,REJECT` 规则，确认后执行 `repair`；随后检查通过。这个范围拒绝被 Surge 接管、却没有经过专用入口的原生 Claude 连接。

以发布包为例：

```sh
SURGE_CC="/Applications/Surge CC.app/Contents/Resources/scripts/surge-cc"
python3 "$SURGE_CC" terminal install --json
python3 "$SURGE_CC" terminal status --json
```

安装命令会先确认程序范围及生效规则，才替换命令入口。此后在项目目录正常执行 `claude`、`claude --resume` 或 `claude auth login`，会先经过 Surge CC 检查；登录使用专用 OAuth 浏览器。检查失败时不运行原版 CLI，也不回退到其他命令或浏览器。标准输入和输出保留给 Claude，接管提示及错误写入标准错误。

v0.5.0 增加「维护 → Orca 启动方式」。点击「检查 Orca」可查看本机连接、受控入口与各启动方式的范围；选择已登记的本机 Orca 项目后，可点击「在 Orca 打开受控终端」。这个入口使用已核验的绝对 `claude` 包装器路径，不依赖 shell 别名或 Orca 自定义启动路径。它只创建一个新终端，不向正在使用的终端发送命令；终端创建成功也不等于线路或账号检查通过，真正的检查在新终端中执行。

Orca 1.4.237 已实测内置终端、标准「新建 Claude」终端入口，以及 Native Chat 标准新建聊天的最小请求经过受控入口；具体条件见 [VALIDATION.md](VALIDATION.md)。这不代表所有自定义启动配置均已接管。**旧 Native Chat 恢复、Orca managed accounts 的账号目录和完整恢复流程仍需单独验证。**Orca 的账号选择不等于 Surge CC 的 A/B，受控 CLI 仍使用 Surge CC 当前工作区；不会导入 Orca 账号凭据。

接管按命令路径生效，不依赖终端窗口名称。Orca 若设置了其他 Claude 可执行路径，需要先改回被接管的入口，或使用上述受控终端按钮；远端 Orca、SSH 目标机器和直接执行其他路径的程序不在本机启动接管范围。普通项目使用所选 Surge CC 工作区的 Claude 数据目录，已登记隔离项目使用其独立 HOME；都不会自动导入原有 `~/.claude` 登录和会话。

**Devin CLI 等其他客户端即使用了 Claude 模型，也不会因此被这个 `claude` 入口接管。**本工具不通过模型名称识别或接管其他程序。

`claude --version` / `claude -v` 仅读取安装时记录并校验过的本地版本，不启动原生程序，也不表示线路检查通过。安装入口变动、备份缺失或原始二进制变化时会拒绝运行；不要手工覆盖包装器。

终端接管保留所有启动必需检查，但跳过可选的外部 DNS 测量，减少终端宿主等待时间。需要查看完整 DNS 观测时，从 GUI 执行「检查线路与隐私」或运行 `check`。

### 更新与维护中心

v0.5.0 起，更新和常见故障处理集中在 App 的 **「维护」** 页。维护操作保留 A/B 浏览器资料、CLI 凭据与线路设置；不会修改个人 Chrome、其他代理节点或自动发起登录。完成修复后重新检查线路，修复成功本身不表示线路通过。

**Claude Code 出现「原始程序已变化」或入口缺失：** 点击「修复终端接管…」，查看核验及修改计划，再确认执行。计划绑定当前程序、包装器、后端与配置；预览后任何相关文件变化，或计划超过 30 分钟，都会要求重新预览。只接受可验证的官方 macOS 原生安装：固定 Anthropic Developer ID 团队、Claude Code 签名标识及 Apple 信任链，验证后才在空白临时环境中读取版本。未知程序、无法识别的链接和签名不符不会被直接接受或覆盖。

**更新 Claude Code：** 先保存并正常关闭受控浏览器和 CLI，点击「更新 Claude Code…」，预览后执行。维护中心通过已配置的本机代理下载官方最新版本，核对发布清单 SHA-256、文件大小及上述 Apple 发布者签名，再重新登记程序。维护期间保留受控包装器，不先恢复成可直接启动的原生链接；账号启动门禁、工作区锁和持久维护标记阻止并发启动。提交失败会尝试恢复本次替换的记录；遇到并发修改或无法确认恢复状态则继续阻止启动，保留恢复文件供后续检查。

原版本文件保留，新版本必须已在现有 CLI 旁路保护范围内。若仅配置了某一个版本文件，而没有官方 `versions/` 目录范围，先通过配置向导调整该范围并检查；维护中心不会擅自扩展 Surge 规则。Homebrew、npm、自定义目录和未知安装布局不在这一自动维护流程内。

受控 CLI 子进程继续设置 `DISABLE_UPDATES=1` 与 `DISABLE_AUTOUPDATER=1`，拒绝在普通会话中直接执行 `claude update`、`upgrade` 或 `install`；这些限制只作用于受控子进程。更新维护中心不运行远程安装脚本，也不读取或复制旧账号的配置来运行版本探测。官方原生安装与签名说明见 [Claude Code 官方文档](https://code.claude.com/docs/en/setup#binary-integrity-and-code-signing)。

命令行使用同一流程：

```sh
SURGE_CC="/Applications/Surge CC.app/Contents/Resources/scripts/surge-cc"
python3 "$SURGE_CC" maintenance status --json
python3 "$SURGE_CC" maintenance plan --operation repair-terminal --json
# 核对返回的 actions 后，将真实 plan_id 填入下一条命令：
python3 "$SURGE_CC" maintenance apply --plan-id '<plan_id>' --json
# 更新版本的预览，将 operation 改为 update-claude：
python3 "$SURGE_CC" maintenance plan --operation update-claude --json
```

**常见错误下方的处理按钮：** 浏览器占用进入专用窗口恢复；原生程序变化进入维护计划；Surge 未运行或模式不合适时打开 Surge；规则异常进入线路修复预览；出口不符时打开线路设置供核对。不会把探测到的新 IP 自动改成预期 IP，也不会把另一处终端故障当作当前网络错误的原因。权限缺失时打开对应系统设置，系统仍可能要求用户完成身份确认。

### 升级 Surge CC

在「维护 → Surge CC 更新」中点击「检查新版本」，查看正式发布说明后选择「下载并校验」，再点击「安装并重新打开…」。只检查或下载不会替换 App，不会在后台定时自动安装。

更新器只接受本仓库的正式发布，检查安装包大小、SHA-256、解压路径、应用标识、版本、代码签名完整性、处理器和系统要求。安装前要求受控会话空闲，在原路径替换 App；新版基础自检失败时回滚，成功后保留旧 App 备份并重新打开。工作区和代理配置位于 App 之外，更新流程不迁移或覆盖它们。当前应用内安装包更新仅适用于 Apple Silicon；源码构建及 Intel 机器继续手动维护。

**这与 Claude Code 的发布者签名验证不同：Surge CC 发布包仍使用 ad-hoc 签名，未经过 Apple 公证。** GitHub 发布和配套校验清单是当前分发信任来源；SHA-256 可发现下载损坏，不能抵御发布账号本身被攻破。安装新版后 macOS 仍可能要求重新开启应用管理等权限，固定 Developer ID 签名问题尚未解决，见 [SIGNING.md](SIGNING.md)。

手动应急升级仍可使用：保存工作并正常关闭专用会话和 Surge CC，备份旧 App，把验证过的新 App 放回**原来的完整安装路径**，再执行 `terminal status --json`、`claude --version` 和线路检查。同路径替换不需要先卸载终端接管；版本查询只读取受控登记，不代替线路检查。

App 移动到其他路径或终端入口指向独立后端时，需要先恢复其已登记的后端位置，或由维护人员使用 `terminal.update_backend` 原子重新绑定到新版后端；不能仅替换另一份 GUI 就认为终端已更新。不要手工编辑 manifest 来接受未知二进制，也不要为更新而临时移除包装器。自定义配置路径应在每条命令的子命令前保留 `--config '/absolute/path/to/config.json'`。

### 明确撤销终端接管

只有决定不再由 Surge CC 接管 `claude` 时，才运行：

```sh
python3 "$SURGE_CC" terminal uninstall --json
```

卸载只恢复能够验证的原始命令链接，不删除工作区、登录资料或项目，也不会自动删除 Surge 中的旁路拒绝规则。撤销后该命令不再执行 Surge CC 的启动检查。程序或入口已经变化时可能拒绝卸载，应先从维护中心核验处理；这不是日常升级的必要步骤。

### OAuth 登录

v0.3.0 提供可选的[钥匙串长效 Token 模式](TOKEN-AUTH.md)，用于受控终端中的 Claude Code；启用后不自动打开网页登录。该功能需要终端入口实际指向包含此实现的后端，不能仅凭安装了旧版 GUI 判断已启用。

从 Surge CC 启动本机 Claude Code，或在安装终端接管后执行 `claude auth login`，按官方 CLI 的提示登录即可，无需先打开网页，也无需修改系统默认浏览器。

工具只向这个 CLI 注入私有 `BROWSER` 打开器。收到符合要求的官方授权链接后，核对线路与实际出口，再打开专用授权窗口。普通网页、脚本入口与 OAuth 统一使用当前工作区的 `Browser/Default`，复用这份专用资料已有的登录状态。旧版 `OAuthBrowser` 资料保留但不再用于启动；不会复制或合并账号资料。

仅本次授权的精确回调端口可直连，且须确认监听者是当前受控 CLI；不会开放整个 localhost 或局域网。检查失败时拒绝打开，CLI 结束时关闭它持有的授权窗口。授权所需的回调参数在 Chrome 启动时设置，因此授权前需先正常退出已有专用网页窗口；占用时提示关闭再重试，不会转到空白资料或个人 Chrome。

CLI 仍负责 state、PKCE、令牌交换及凭据保存。Surge CC 的启动脚本和状态回执不记录授权 URL、state 或授权码；浏览器登录资料仍由 Chrome 管理。远端、附着、桌面及后台等不支持的入口会被阻止；第三方 MCP OAuth 不在授权白名单中。

如果用户或项目设置启用了 `remoteControlAtStartup`，受保护启动会仅为本次子进程合并 `remoteControlAtStartup:false`，不修改原设置文件。显式 CLI 参数要求远端启动，或企业托管设置强制开启时，仍拒绝启动。

### 专用浏览器语言

在设置中的「专用浏览器语言」填写 `en-US` 可选择美式英语；其他合法语言标签同样支持。正常关闭专用网页和授权窗口后，下次通过受控入口启动时会更新共同使用的专用浏览器语言。0.2.4 同时写入 Chrome 的语言列表和选中语言，避免旧选中值在重启后覆盖新设置。留空会保留专用资料原有的语言偏好，不修改个人 Chrome 或系统语言。

**网站界面语言可能另有保存值。**浏览器使用英语并不保证 Claude 页面立即使用英语：网站自己的 Cookie、localStorage 或账号语言偏好可能继续生效。Surge CC 不会自动删除、改写或同步这些网站数据，网页和 OAuth 使用同一份专用资料，网站偏好随该资料保留。需要时在站点语言设置中调整。

### 快照与恢复

先正常结束对应工作区的网页和 CLI，再保存快照。恢复会先校验快照、备份当前数据，并保留替换前目录。

快照只复制当前工作区的 `data` 目录，可能包含网页 Cookie、历史记录和原生 OAuth 的 `.credentials.json` 明文回退文件，应私下保存。它不包含钥匙串 Token 文本、工作区外的凭据引用、线路设置或项目源码，也不是整套账号的迁移包。恢复不会改变另一工作区的凭据或自动切换钥匙串认证。A/B 不代表独立设备或身份，项目内容、系统和服务端关联仍可能共享。

## 检查结果怎么看

界面把结果分成「启动必需」「补充待确认」「补充信息」。**未确认不等于已发现泄漏，信息也不等于完整安全保证。**

v0.3.0 明确区分「保护已挂起」与「线路检查通过」。全局代理模式下暂停固定出口与断线阻断，允许专用网页、非隔离 Claude Code 和 OAuth 按 Surge 全局策略运行；已登记隔离项目从 v0.5.1 起要求规则模式；检查不会显示绿色通过。切回规则模式后重新检查，才恢复指定出口保护。直连模式暂停启动，未知模式或无法读取状态则按失败处理；应用不自动切换 Surge 模式。

| 检查 | 能说明什么 | 不能说明什么 |
| --- | --- | --- |
| 固定线路与出口 | 当前代理入口、规则、节点选择和精确公网 IP 符合配置 | 未来所有时刻都保持相同状态 |
| DNS 接管 | 系统与 Surge 对测试域名的解析存在接管迹象 | FakeIP 不能证明最终递归 DNS 公网出口 |
| 专用代理 DNS 出口 | 一次新建的 12 个随机域名测试，观察权威端收到的解析器查询，并前后核对线路 | 不是整台 Mac 的所有 DNS；解析器 IP 不必等于代理 IP |
| WebRTC | 临时 Chrome 的真实 ICE 候选、错误及完成情况 | 无候选本身不能证明没有旁路；已有资料中的扩展行为也不完全等同于临时探针 |
| IPv6 | 本机接口地址与默认路由的时点清单 | 出现 IPv6 或 utun 不等于泄漏；清单也不是完整 IPv6 外部测试 |
| 时区、语言、地区 | 展示本机或浏览器设置；可与显式预期比较 | 不证明实际所在地，也不会自动改变系统设置 |
| GeoIP 与 ASN | 查询保存的预期 IP 对应的数据库信息，实际出口另行核验 | 运营商品牌、国家标签或 ASN 不证明真实家庭宽带 |

规则模式默认开启严格隐私检查：相关必需项无法确认时阻止启动。发现额外公网 ICE 地址时，即使关闭严格检查也会阻止启动。预期时区、地区、国家、ASN 和浏览器语言留空时不作所在地推断；填写后相应比较会参与启动判断。

DNS 外部观测是补充诊断。服务返回完整有效结果且前后线路一致时，显示「已实测」，可展开查看时间、解析器与范围。`split` 提示核对分流；`inconclusive`、超时、限流、截断或结果不完整均保留未确认。观测过程中实际出口、保护范围或配置发生异常则为必需失败，撤回启动资格。

DNS 的地区及 Anycast 标签不单独作为泄漏依据。权威端看到解析器的 IPv6 地址，也不证明 Mac 的 IPv6 绕过了代理。

## 断线保护的范围

以下保护适用于 **Surge 规则模式**。专用入口固定到只有一个节点的组，不配置自动备用出口；浏览器同时使用显式 HTTP 代理、禁用 QUIC、限制非代理 WebRTC UDP，并核验 Surge 对专用应用旁路连接的拒绝规则。

终端接管增加两层约束：被接管的命令先检查再启动；配置中的原生 Claude 程序路径在 Surge 内拒绝绕过专用入口的连接。直接执行原始版本二进制仍可能启动进程，但其被 Surge 接管的旁路流量应命中拒绝规则。命令接管不等于操作系统禁止运行原始程序，路径规则也不会自动覆盖复制到其他位置的二进制或共享解释器下的其他安装。

运行监控默认每 **10 秒**检查一次，实际出口目标复查间隔至少 **30 秒**，检测命令自身耗时会延长间隔。发现异常或无法确认时，尝试结束它持有的程序并记录结果，不通过进程名关闭个人 Chrome。

普通网页和非隔离 CLI 保留全局代理模式的挂起行为：识别后固定出口保护暂停，出口由 Surge 全局策略决定，切回规则模式后重新核验。**已登记隔离项目的开发入口不采用此例外**：必须处于规则模式，变化或检查失败后关闭本次开发代理并停止受控会话，不允许改用其他出口。运行检查仍有轮询与命令执行延迟，不是模式切换瞬间的原子防火墙操作；不修改个人 Chrome 或 Surge 配置。

以下情况不能承诺即时断网：

- Surge 被关闭、增强模式失效，或实际流量没有被 Surge 接管。
- 轮询尚未发现变化，监控进程被强杀，或子进程自行脱离。
- CLI 的 MCP、外部脚本等忽略代理环境，或从其他入口启动的程序。

运行巡检不重复 DNS、WebRTC、时区或 ASN 全套测试，也不持续抓包。即使本次检查通过，也不是全系统防泄漏证明。详细实现约束见 [INTERFACE.md](INTERFACE.md)。

基线域名包括 `claude.ai`、`claude.com`、`platform.claude.com`、`code.claude.com`、`api.anthropic.com`、`console.anthropic.com`、`statsig.anthropic.com`、`claudeusercontent.com`、`claudemcpcontent.com`、`claude.app`。可扩展清单，不能移除基线；清单不能保证覆盖未来新增域名和第三方资源。

## 常见问题

**为什么提示 DNS 未确认？**

可能是外部服务限流、超时、回执不完整，或没有配置专用浏览器范围。展开该行查看原因，恢复条件后重新完整检查。不要用修改文案或关闭严格检查代替排查。递归器地址与代理出口不同本身正常。

**为什么提示专用窗口仍在运行或有锁？**

窗口关闭后，专用 Chrome 主进程或运行时锁可能还存在。v0.3.0 可点击报错下的 **关闭专用窗口并修复**，也可从「工作区 → 当前工作区的专用浏览器」操作。它只对经过核验的当前专用工作区窗口请求正常退出，会中断其中的网页和授权；请先保存未提交的内容。

恢复器核对进程的用户、可执行程序、启动身份和专用资料目录，等它正常退出后取得浏览器及授权独占锁。工作区空闲时使用独占锁；有普通 CLI 会话时使用共享锁，并在清理期间暂时阻止新启动及账号切换。两种情况都阻止同时备份或恢复工作区。复核 PID 与本地通信端点后，将确认过期的 Chromium 锁链接归档到私有恢复目录。普通 Claude CLI 会话可以继续运行，不需要为修复浏览器而结束工作。仍在进行的授权、浏览器启动或工作区备份操作会阻止清锁；无法核实身份、其他主机锁或退出超时时也不会强行清理。登录资料、个人 Chrome、另一个工作区和 Surge 配置均保留。

旧版曾把普通 CLI 持有的工作区共享锁也当作修复障碍，导致专用窗口关闭后未能完成清锁，Dock 快捷入口仍提示残留锁。修复版将浏览器恢复与普通 CLI 会话区分开，仍严格排除活动浏览器和 OAuth。

成功后 App 自动重新执行完整线路检查，但不会自动打开网页、启动 Claude 或登录。修复成功本身不代表线路通过；命令行 `browser-locks recover` 只完成恢复，需另行运行 `check`。

0.2.5 起的离线 **仅清理已退出窗口的残留锁** 入口仍保留，对应 `browser-locks repair`。它不请求结束任何进程，只处理确认已经退出的窗口；v0.3.0 的 App 调用它成功后也会自动重新检查。0.2.6 及以前的 App 按钮仍叫「检查并修复浏览器锁」，成功后需手动重新检查。

**全局模式下可以继续打开网页和 Claude Code 吗？**

普通网页和非隔离 CLI 可以，已登记隔离项目从 v0.5.1 起必须使用规则模式。Build 11 起，明确的全局代理模式显示「保护已挂起」，仍可通过 App、已接管的 Ghostty / Orca 终端启动，也可使用专用 OAuth 窗口。流量依 Surge 全局策略，Surge CC 此时不承诺固定出口或断线即阻断；橙色挂起状态不会被当作线路通过。规则模式恢复后重新检查才能恢复保护。直连、未知或不可读取的模式仍阻止启动。

**必须更改系统时区、语言或关闭 IPv6 吗？**

不需要。工具只读展示这些设置，修复器不会自动修改它们。填写预期值仅用于比较。

**会影响现有节点吗？**

检查本身不修改 Surge。确认修复后，会修改指定组、相关规则及专用监听入口，并可能重载配置；无关节点定义和规则会保留。应用前请核对计划。托管配置、模块或临时规则覆盖可能需要手动处理。

**代理 IP 变了怎么办？**

工具会阻止启动。先确认变化原因；确实更换了自己的出口后，更新预期 IP 并重新检查。工具不会自行把新地址视为可信出口。

**没有独立 Chrome 可以用吗？**

留空 `browser_path` 时存在普通 Chrome 兼容路径，但没有独立应用范围核验。专用浏览器保护、DNS 外部观测和受控 OAuth 按本 README 的完整配置使用，不应把兼容路径理解为同等保护。

## 数据与隐私

默认数据位于 `~/Library/Application Support/Surge CC/`。自定义配置路径时，数据使用其父目录。

| 位置 | 内容 |
| --- | --- |
| `config.json` | 当前工作区的有效设置与共享机器设置，文件权限 `600` |
| `workspaces/<名称>/settings.json` | 各工作区的线路及检查设置 |
| `workspaces/<名称>/keychain-auth.json` | 认证方式与钥匙串引用，不含 Token 文本 |
| `workspaces/<名称>/data/` | 专用网页、OAuth 和 CLI 数据 |
| `workspaces/<名称>/snapshots/`、`previous-*` | 快照及恢复前保留数据 |
| `sessions/` | 会话配置副本、启动回执及监控状态 |
| `repair-backups/` | 修复前配置备份，可能含代理凭据 |
| `browser-lock-backups/` | 归档的专用浏览器运行时锁及修复清单 |
| `launchers/` | 用后清理的临时 Terminal 启动脚本 |
| `terminal/` | 终端接管清单、原始链接备份及锁；默认位于本工具的 Application Support 目录 |
| `isolation.json`（可选） | 手动登记的项目路径及独立运行目录；不是账号或会话数据 |

检查会在内存中读取可能包含节点凭据的 Surge 配置，不输出完整配置。JSON 诊断仍可能含本地路径、组名及真实出口 IP，分享前需要脱敏。不要将工作区、快照、配置、备份或 `.local/` 上传到公开仓库。

### 项目文件与旧会话的边界

**0.4.0 提供配置向导和 `project plan/apply/enable` 公共命令**，为审阅后的工程副本及 Orca 关联工作树启用 macOS Seatbelt。只限制受控原生 Claude 及其子进程；普通目录不会自动纳入隔离。向导按明确选择登记项目，原项目不改动。操作见 [项目指南](docs/PROJECTS.md)，底层格式见 [接口合约](INTERFACE.md#已登记项目文件沙箱)。

启用后，主项目副本及独立 HOME 可读写，其他用户资料默认不开放。当前隔离 HOME 和当前项目的插件、skills、commands、hooks 可用；额外 MCP、宿主 IDE/Chrome 和任意目录集成仍关闭。每次启动建立独立开发代理，公网只有 `http://127.0.0.1:62919` 一个上游，本机预览只接通当前子进程树的服务。TLS、依赖和 Git 开发操作的具体范围见 [隔离开发说明](docs/ISOLATED-DEVELOPMENT.md)。

Orca 本机终端的自动标题通过单独的[最小权限标题桥](docs/ORCA-TITLES.md)恢复：只通知已核验的当前标签页，最多转发当前提示词的前 512 个字符，不加载旧账号 hooks 或开放其他项目目录。现有会话需重新启动后接入。

启动器核对 Orca 新工作树与已登记主项目之间的 Git 双向路径关系，为工作树建立独立 HOME。仅复制隔离标记、缺少登记或链接不匹配的目录会被拒绝，不会退回普通启动。

已登记隔离项目的新会话默认使用 **Opus 5.5 / High**。启动器通过受控内联设置传入精确模型 `claude-opus-5-5` 和 `effortLevel: high`，优先于隔离 HOME 和项目的普通设置。显式 `--model`、`--effort` 及会话中的 `/model`、`/effort` 仍可临时覆盖；下一次普通新启动恢复上述默认值。此默认值不修改已运行会话，也不应用于未登记的普通目录。

可为明确授权的隔离项目启用默认目录信任：在隔离根目录的 `.runtime/trust.json` 中列出准确的项目 ID 和主项目路径。启动器完成工作树关联校验后，只在当前独立配置中补入该主项目的信任标记；普通目录和未列出的项目不受影响，已有明确的“不信任”值不会被覆盖。此功能不改变文件沙箱、网络保护、工具权限或 MCP 限制，也不共享历史会话或凭据。配置格式和撤销方式见 [默认目录信任](INTERFACE.md#默认目录信任)。

当前支持 Orca 默认 `~/orca/workspaces/<项目>/<工作树>` 目录布局。工作树源码、同仓库 Git 对象／引用／reflog 和当前工作树状态可写，支持提交、拉取、推送；其他工作树文件、共享 Git config／hooks／关联指针仍受保护。修改远端配置等操作请通过宿主完成。私人远端需要隔离环境自己的授权；不会借用宿主 SSH 或钥匙串凭据。

工作树使用新运行目录，不自动复制主项目的登录资料、会话和记忆。独立运行目录在登记根目录的 `.runtime/` 下，不包含在 A/B 工作区快照中，应单独私下备份。共享 Git 对象仍可能包含该仓库保留的全部历史；文件沙箱不对已经允许读取的代码或 Git 历史脱敏。

已登记项目可以单独启用**同项目、同账号共享对话历史**。启用后，从不同 Orca 工作树启动的 Claude 使用同一个会话目录，原生 `/resume` 可接续该项目的其他对话；源码、HOME、认证、设置和自动记忆仍按原边界隔离，其他项目与账号不可读取此会话库。首次启用必须正常退出相关受控会话，通过 `project enable-plan` 预览，再由 `project enable` 初始化会话库；未初始化的账号会阻止启动，不会借用其他账号历史。原始会话文件保留，详见 [共享项目会话](INTERFACE.md#共享项目会话)。

共享完整对话会包含对话中已有的代码片段和工具结果，但不会授予其他工作树的文件读取权限。历史中指向其他 HOME 的图片、计划或文件回退记录仍可能不可访问。接续同一对话前请先退出原终端；原生 CLI 同时恢复同一会话可能交错写入记录，需要并行探索时使用 `--fork-session` 新建分支。

已登记项目还可单独启用**同项目、同账号的本机跨会话通信**。向导或 `project enable` 为明确选择的项目启用后，启动器为这些项目的 Orca 工作树建立共同的本地会话发现目录和短 Unix socket 路径，解决原生 CLI 无法创建 socket 目录时的 `Cross-session messaging is off` 提示。各工作树 HOME、源码访问、登录凭据和记忆仍保持原有边界，其他项目和账号不获准访问该通信空间；共享对话历史仍由上面的独立配置决定。配置和迁移规则见 [本机跨会话通信](INTERFACE.md#本机跨会话通信)。

更新后需正常退出并重新启动旧 Claude 进程，通信双方均使用新版受控入口才会进入同一空间。该功能保留 Claude 原生消息权限确认和等待审批状态，不自动替用户批准消息；远端控制、跨机器会话发现及自动上传会话保持关闭。只增加本项目通信目录的访问权限，不新增外网、DNS 或其他本机 TCP 出站权限，也不改变 已有指定节点的线路保护。它仍是受控进程的有限权限配置，不是整机通用网络隔离。

已接管的隔离交互终端支持 Orca 图片粘贴：收到完整粘贴片段中的精确 `orca-paste-<时间戳>-<UUID>.png` 临时路径后，启动器校验并复制图片到当前隔离 HOME 的私有目录，再把副本路径交给 Claude；单图上限 **20 MiB**。原系统临时目录仍不开放，导入副本随该工作树 HOME 保留，供恢复会话使用。安装更新后，已运行的 Claude 会话需退出重启。普通输入、非交互调用、个人 Chrome 和现有线路保护不变。范围与失败行为见 [Orca 终端图片粘贴](INTERFACE.md#orca-终端图片粘贴)。

在已登记的项目或关联工作树中，可用已接管的 `claude --surge-cc-isolation-check` 检查文件与网络边界。该诊断执行本机临时文件探针、Git 状态与权限探针和原生 CLI `--help`，也执行基础线路检查；不登录、不向模型发送提示词，结果不等于所有实际工作流程均已验收。

对于未启用上述文件沙箱的普通项目，`CLAUDE_CONFIG_DIR` 只将原生 CLI 的默认数据位置指向所选工作区，**不是文件系统沙箱，也不是内容脱敏器**。CLI 仍在原项目目录运行，可能加载项目及上级目录的指令、设置或记忆，或通过工具读取源码、日志、Git 历史和可访问的其他文件。`--resume`、`--continue` 等参数没有被统一禁用；本工具不会筛除恢复会话中的资料。

普通项目启动器会过滤已知 Claude 认证覆盖变量，继承其余终端环境，并覆盖受保护的代理、浏览器打开器、工作区和更新变量；它不会清空所有环境变量，也不移除其他工具的全部 API Key 或凭据。配置检查关注与受控启动冲突的设置，不等同于对 hooks、MCP、工程文件或数据内容完成安全审计。

需要减少旧资料进入新会话时，可另建经过审阅的工作副本，只保留源码、测试、必要文档和技术交接摘要，并使用新会话。需要阻止工具读取副本外的资料时，还应配置实际的文件访问限制；新文件夹、Git worktree、`.gitignore` 或 A/B 工作区本身不提供这一保证。提供给云端模型理解的代码和上下文仍会发送给模型服务。

### 外部检查服务

检查涉及以下外部服务：

| 服务 | 用途与披露的数据 |
| --- | --- |
| `api.ipify.org` | 测量公网出口，服务可见请求来源 IP |
| `api.anthropic.com/v1/models` | 无登录凭据的 HTTPS 连通性请求；401/403 只说明收到响应，不代表账号可用 |
| `ipwho.is` | Surge 数据库查询无有效结果时的备用 GeoIP/ASN 查询，查询保存的预期 IP |
| Google STUN | 浏览器 ICE 探测；可能发送 UDP，服务可见该次实验的来源地址 |
| `dnsleak.dev` / `*.t.dnsleak.dev` | 随机域名权威观测，可见代理出口及解析器查询；不发送 Claude 账号、会话或项目内容 |

DNS 观测每次新建测试，不复用旧报告，不直连回退、不跟随跳转、不跳过证书验证；快速检查、运行巡检和 OAuth 内部复核不重复此补充测量。第三方服务的处理方式见其 [API 文档](https://dnsleak.dev/api) 与 [隐私说明](https://dnsleak.dev/privacy)。

工具还会通过系统和 Surge 解析器查询 `claude.ai`，并用带随机令牌的本机回环服务接收临时浏览器检测回执。无需 Surge HTTP API 密钥，不安装 root 常驻服务，不自动清理个人账号或系统钥匙串。

## 命令行

以下命令在源码根目录运行。发布包用户可将 `./scripts/surge-cc` 替换成安装步骤中的 `python3 "$SURGE_CC"`。

```sh
./scripts/surge-cc check --json
./scripts/surge-cc pin --json
./scripts/surge-cc launch web --json
./scripts/surge-cc launch code --terminal --json
./scripts/surge-cc launch code -- --resume
./scripts/surge-cc guard-status --json
./scripts/surge-cc terminal install --json
./scripts/surge-cc terminal status --json
./scripts/surge-cc terminal uninstall --json
./scripts/surge-cc browser-locks recover --workspace A --json
./scripts/surge-cc browser-locks repair --workspace A --json

./scripts/surge-cc workspace list --json
./scripts/surge-cc workspace use --name B --json
./scripts/surge-cc workspace snapshot --name B --label '工作前备份' --json
./scripts/surge-cc workspace restore --name B --snapshot '返回的快照编号' --json

./scripts/surge-cc repair-plan --json
./scripts/surge-cc repair --plan-id '刚核对的计划编号' --json
```

`workspace use` 不带 `--close-sessions` 时要求会话已退出。确认已保存工作、需要一起结束受控网页与 CLI 后，可以显式使用 `workspace use --name B --close-sessions --json`；命令不会自动重新登录或启动任务。凭据状态可用 `workspace-auth status --workspace B --json` 查看，Token 建议在 GUI 安全输入框设置。

`check`、`status` 和 `checkdetail` 在规则模式执行完整实时检查，在全局代理模式返回挂起状态；`guard-status` 才是读取已有监控回执。全局 `--config PATH` 放在子命令前。CLI 在当前目录运行，GUI 使用所选项目目录。

`browser-locks recover` 先请求当前专用窗口正常退出，再归档确认过期的锁；`browser-locks repair` 只清理已退出窗口的残留锁，不结束进程。两个命令都不自动执行线路检查、登录或启动，完成后需运行 `check`；App 中的对应按钮会在成功后自动重新检查。

`configure` 还支持 `--expected-timezone`、`--expected-locale`、`--expected-country`、`--expected-asn` 和 `--browser-language`，用空字符串清除预期值。再次配置时需继续传入要保留的 `--profile`，否则清空该路径；省略 `--browser-path` 保留旧值，显式空字符串则取消独立应用范围设置。

Claude Code 参数须位于 `--` 后。`--settings` 只接受通过语义检查的内联 JSON，不接受临时设置文件路径；`--setting-sources` 只接受 `user`、`project`、`local` 的非空、无重复组合。不能覆盖专用代理、浏览器打开器、工作区或更新限制。成功退出码 `0`，检查阻止或普通报告模式的受监控会话非零结束为 `2`，捕获的系统错误为 `1`；终端的 `--passthrough` 模式保留已启动子进程的退出码。详细 JSON 和退出码约定见 [INTERFACE.md](INTERFACE.md)。

## 从源码构建

后端仅使用 Python 标准库，界面使用 SwiftUI / AppKit。构建另需 Apple Command Line Tools。

```sh
git clone https://github.com/jsjixu/surge-cc.git
cd surge-cc
python3 -m unittest discover -s tests -v
./scripts/test-gui.sh
SURGE_CC_APP_NAME='Surge CC 0.5.1.app' ./scripts/build-app.sh
```

使用 v0.5.1 源码时，输出为 `dist/Surge CC 0.5.1.app`，只构建当前机器架构。默认使用开发用 ad-hoc 签名，更新后可能需要重新授权 macOS 隐私权限；浏览器恢复和暂停提示没有改变这一限制。若要使用固定代码签名证书，设置 `SURGE_CC_SIGNING_IDENTITY` 为有效证书的 SHA-1 指纹或精确名称；证书缺失或签名失败会停止，不自动降级。证书申请、首次迁移、升级前连续性验证与公证边界见 [固定签名指南](SIGNING.md)。

构建不会安装、启动应用或修改代理。已有同名输出会被拒绝；用 `SURGE_CC_APP_NAME` 或 `SURGE_CC_DIST_DIR` 选择新文件名或目录，不会覆盖正在使用的应用。

各版本的测试数量、构建与真机验收条件，以及未覆盖的范围见 [VALIDATION.md](VALIDATION.md)。

反馈问题时请提供版本、macOS / Surge / Chrome 版本、复现步骤和脱敏后的具体检查项；不要附登录令牌、完整代理配置、个人路径或工作区快照。参与开发请阅读 [贡献说明](CONTRIBUTING.md)。
